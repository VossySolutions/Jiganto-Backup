## Quick start

### 1. Install one optional dependency
```bash
npm install xlsx        # only needed for Excel import/export
```
The component uses a dynamic `import('xlsx')` so it won't break if xlsx is absent — the export button will just notify the user.

### 2. Copy the files into your project
```
src/
  components/
    GanttChart.tsx      ← the component
    gantt.types.ts      ← types + adapter
  pages/ (or app/)
    gantt/
      page.tsx          ← copy GanttPage.tsx here, rename as needed
```

### 3. Use it
```tsx
import GanttChart from '@/components/GanttChart';
import { pmTaskToGanttTask } from '@/components/gantt.types';

// Transform your pm_tasks rows
const tasks = rawTasks.map(pmTaskToGanttTask);

<GanttChart
  tasks={tasks}
  resources={resources}
  dependencies={deps}
  onTaskUpdate={async (task) => { await api.updateTask(task.id, task); }}
  onTaskAdd={async (task)   => { await api.createTask(task); }}
  onTaskDelete={async (id)  => { await api.deleteTask(id); }}
/>
```

## pm_tasks mapping

The `pmTaskToGanttTask` adapter handles the most common schema automatically:

| Your column | Maps to |
|---|---|
| `id` | `GanttTask.id` |
| `title` | `GanttTask.name` |
| `status` | normalised to `GanttStatus` (see STATUS_MAP) |
| `priority` | normalised to `GanttPriority` (see PRIORITY_MAP) |
| `assignee` | `GanttTask.resources[0]` |
| `due_date` | `GanttTask.end` (start defaults to same day) |
| `parent_id` | `GanttTask.parent` |

If your schema uses different column names, just call the constructor directly:

```ts
const task: GanttTask = {
  id:       row.task_id,
  name:     row.task_title,
  type:     'task',
  start:    row.start_date ?? row.created_at.split('T')[0],
  end:      row.due_date,
  status:   STATUS_MAP[row.state] ?? 'notstarted',
  priority: PRIORITY_MAP[row.urgency] ?? 'medium',
  resources: row.assigned_user ? [row.assigned_user] : [],
  parent:   row.parent_task_id ?? null,
  progress: row.completion_pct ?? 0,
};
```

## Component props

```ts
interface GanttChartProps {
  // Required
  tasks:        GanttTask[];
  resources:    GanttResource[];
  dependencies: GanttDependency[];

  // Callbacks (all optional — omit for read-only)
  onTaskUpdate?:       (task: GanttTask) => void;
  onTaskAdd?:          (task: GanttTask) => void;
  onTaskDelete?:       (id: string)      => void;
  onDependencyChange?: (deps: GanttDependency[]) => void;
  onResourceChange?:   (resources: GanttResource[]) => void;

  // UI options
  defaultView?:   'day' | 'week' | 'month' | 'year';   // default: 'week'
  defaultZoom?:   number;                                // default: 100
  editable?:      boolean;                               // default: true
  theme?:         'dark' | 'light';                      // default: system
  customColumns?: GanttColumn[];                         // extra schema columns
  className?:     string;
}
```

### Read-only mode
```tsx
<GanttChart tasks={tasks} resources={resources} dependencies={deps} editable={false} />
```

### Custom columns (e.g. "Source" from pm_tasks)
```tsx
<GanttChart
  tasks={tasks}
  resources={resources}
  dependencies={deps}
  customColumns={[
    { id: 'source', label: 'Source', w: 90, visible: true, dataType: 'text' },
  ]}
  onTaskUpdate={...}
/>
// Then populate task.custom['source'] = row.source in your adapter
```

### Improvements over v11 HTML

| Area | v11 HTML | React component |
|---|---|---|
| Data | Hard-coded seed data | Fully controlled via props |
| Types | None | Full TypeScript 5 interfaces |
| State | Global `let` variables | `useReducer` with typed actions |
| Performance | Full DOM re-render on every change | React reconciler, memoised derivations |
| Scroll | Manual DOM sync | `useEffect` scroll sync |
| Undo | Object clones in plain array | Immutable snapshots in reducer |
| Custom columns | Basic | Typed with text/number/date, schema-drivable |
| pm_tasks adapter | None | `pmTaskToGanttTask()` with STATUS_MAP/PRIORITY_MAP |
| Styling | Inline `<style>` tag | Scoped CSS vars + Tailwind utilities |
| Controlled | No | Yes — Gantt reports changes, you own persistence |
| Tree-shaking | N/A | xlsx loaded dynamically (no bundle cost if unused) |

## Known Stage 2 items (not in this release)

These require design decisions from you about your data model:

- **Baseline comparison** — overlay a saved baseline vs current dates as two stacked bars
- **Levelling** — auto-shift tasks to resolve over-allocation (requires float/slack calculation)
- **Real-time collaboration** — Supabase realtime or WebSocket integration
- **Gantt-to-board sync** — bidirectional sync if Jiganto also has a Kanban board

All of these are additive — they do not require changing the existing component API.
